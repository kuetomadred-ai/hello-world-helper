# حزمة تنفيذ PLUTUS — أمان الخادم ومحرك المخاطر

هذه الحزمة مهيأة للمستودع الحالي `kuetomadred-ai/hello-world-helper` وليست قالباً عاماً. استخدم `MASTER_IMPLEMENTATION_PROMPT.md` كنص المهمة للذكاء الاصطناعي المتصل بالمستودع، ثم أرفق ملف ZIP معه.

## محتويات ZIP

- `MASTER_IMPLEMENTATION_PROMPT.md`: قيود صارمة تمنع تغيير واجهة التداول بصرياً، وتحدد مراحل التنفيذ وبوابات الاختبار.
- `backend/src/security.ts`: أساس حماية Fastify: رؤوس HTTP، request IDs، وrate limiting.
- `backend/src/risk.ts`: دوال حساب المخاطر وحالة الحساب، بما فيها drawdown وقواعد التحدي والأهلية المحاكية للسحب.
- `backend/src/security.test.ts` و`backend/src/risk.test.ts`: اختبارات وحدات مرجعية لحدود الأمان والحسابات الأساسية.
- `supabase/migrations/20261019000000_security_hardening.sql`: مخطط توسعي لإعداد metrics/audit/risk profiles وبيانات التنفيذ.

## طريقة الاستخدام

1. افتح مستودع PLUTUS عند الذكاء الاصطناعي وأنشئ فرع عمل من `main`.
2. أرسل محتوى `MASTER_IMPLEMENTATION_PROMPT.md` أولاً، ثم أرفق ZIP.
3. اطلب منه مراجعة كل ملف ومقارنته بالمخطط والدوال الحالية قبل الدمج؛ لا تسمح بنسخ أعمى أو الانتقال بين المراحل عند فشل الاختبارات.
4. راجع diff والاختبارات. الـmigration للتدقيق والمراجعة فقط، ولا تُطبّق على Supabase إلا بعد فحص المخطط الحي وموافقة منفصلة.

## الحدود المهمة

الحزمة لا تنشر backend ولا تعدّل تطبيق PLUTUS أو Supabase. معدل الطلبات داخل الذاكرة يعمل لنسخة واحدة فقط؛ يلزم مخزن مشترك موثوق قبل تشغيل عدة نسخ. قواعد prop firm والأخبار والسحب هنا محاكاة؛ لا توجد معالجة دفعات أو مزود أخبار حي مضمّن. حساب الهامش وP&L يحتاج تأكيد عملة `tick_value`/تحويل العملات قبل اعتباره دقيقاً لكل أداة.

الواجهة غير مستهدفة بصرياً. لا تغيّر ملفات HTML/CSS أو الأصول أو التخطيط؛ أي تعديل برمجي ضروري للربط يجب أن يكون محدوداً ويثبت عدم وجود فرق بصري.
